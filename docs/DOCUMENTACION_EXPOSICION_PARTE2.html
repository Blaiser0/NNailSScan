ScanRecord.kt Modelo de datos

app/src/main/java/com/example/nnailscan/data/model/ScanRecord.kt

Clase de datos que define qué información se guarda cada vez que un usuario analiza una uña. Es la “ficha” del escaneo en Firestore.

  • id / userId — identifican el escaneo y al usuario dueño.
  • result / rawLabel — nombre legible y etiqueta cruda del modelo IA.
  • confidence — porcentaje de confianza del diagnóstico.
  • imageUrl — enlace a la foto guardada en Firebase Storage.
  • dictionaryTermId — conecta el resultado con el diccionario médico.
  • createdAt — fecha y hora del escaneo.
⭐ Código más importante para la diapositiva — definición del registro
data class ScanRecord(
        val id: String = "",              // ID único del escaneo
        val userId: String = "",          // UID de Firebase Auth
        val result: String = "",          // "Onicomicosis" (legible)
        val rawLabel: String = "",       // "onicomicosis" (del modelo)
        val confidence: Float = 0f,       // ej. 87.3
        val imageUrl: String = "",        // foto en Firebase Storage
        val dictionaryTermId: String = "",// enlace al diccionario
        val createdAt: Timestamp? = null, // cuándo se hizo el escaneo
)
Qué decir en la exposición:
“Cada vez que alguien escanea una uña, la app crea un ScanRecord con el diagnóstico, la confianza, la foto y la fecha. Ese objeto es el que se guarda en Firestore y aparece después en el historial del usuario.”

ScanScreen.kt Pantalla de escaneo

app/src/main/java/com/example/nnailscan/ui/screens/ScanScreen.kt

Pantalla donde el usuario elige o toma la foto de su uña. Valida sesión, muestra carga y coordina el análisis completo.

  • pickImageLauncher — abre la galería del celular.
  • takePictureLauncher — abre la cámara para tomar foto.
  • isProcessing — muestra el spinner “Analizando…”.
  • processScan() — función central que orquesta todo el flujo.
⭐ Código más importante para la diapositiva — función processScan()
private fun processScan(bitmap: Bitmap, ...) {
    // 1. Verificar que hay usuario logueado
        val userId = authRepository.currentUser?.uid
        if (userId == null) {
            Toast.makeText(context, R.string.error_not_authenticated, ...).show()
            return
        }

    scope.launch {
        onProcessingChanged(true)   // mostrar spinner

        // 2. Clasificar imagen + subir foto + guardar ScanRecord
            val result = scanRepository.processAndPersistScan(
                context = context,
                userId = userId,
                bitmap = bitmap,
            )

            onProcessingChanged(false)

        result.fold(
            onSuccess = { payload ->
                ScanSessionState.current = payload
                onNavigateToResult()  // ir a pantalla de resultado
            },
            onFailure = { error -> Toast.makeText(context, ...).show() },
        )
    }
}
Qué decir en la exposición:
“El usuario solo toca un botón para elegir foto o cámara. Esta función verifica que esté logueado, manda la imagen al repositorio para analizarla y guardarla, y si todo sale bien navega a la pantalla de resultado.”

NailScanNavGraph.kt Navegación UX

app/src/main/java/com/example/nnailscan/navigation/NailScanNavGraph.kt

El “GPS” de la app. Define todas las rutas y conecta las pantallas: decide por dónde empieza y cómo fluye el escaneo.

  • NailScanRoutes — nombres de cada pantalla (scan, main, etc.).
  • startDestination — login si no hay sesión, inicio si ya está logueado.
  • Flujo escaneo — Main → Scan → ScanResult → Main.
  • ScanSessionState — pasa el resultado entre Scan y ScanResult.
⭐ Código más importante para la diapositiva — inicio + flujo de escaneo
// Pantalla inicial según sesión
val startDestination = if (FirebaseConfig.auth.currentUser != null) {
    NailScanRoutes.Main
} else {
    NailScanRoutes.Welcome
}

NavHost(navController, startDestination = startDestination) {

    // Inicio → botón escanear
    composable(NailScanRoutes.Main) {
        MainScreen(
            onNavigateToScan = { navController.navigate(NailScanRoutes.Scan) }
        )
    }

    // Pantalla de análisis
    composable(NailScanRoutes.Scan) {
        ScanScreen(
            onBack = { navController.popBackStack() },
            onNavigateToResult = { navController.navigate(NailScanRoutes.ScanResult) }
        )
    }

    // Pantalla de resultado → volver al inicio
    composable(NailScanRoutes.ScanResult) {
        ScanResultScreen(
            onBack = { navController.popBackStack(NailScanRoutes.Main, false) }
        )
    }
}
Qué decir en la exposición:
“Este archivo conecta todas las pantallas. Si el usuario ya tiene sesión va directo al inicio; si no, ve la bienvenida. El flujo del escaneo es: Inicio → Analizar → Resultado → Inicio. Es la experiencia de usuario completa en un solo mapa.”

build.gradle.kts Infraestructura

app/build.gradle.kts

Archivo de configuración del módulo Android. Define cómo se compila la app y qué librerías habilitan Compose, Firebase, TensorFlow Lite y navegación.

  • defaultConfig — ID de la app, versión y SDK mínimo (Android 7.0+).
  • noCompress "tflite" — evita que el modelo IA se rompa al empaquetar el APK.
  • Compose — framework de interfaces modernas.
  • Firebase — Auth, Firestore y Storage para usuarios e historial.
  • TensorFlow Lite — ejecuta el modelo de IA en el celular.
⭐ Código más importante para la diapositiva — config + dependencias clave
defaultConfig {
    applicationId = "com.example.nnailscan"
    minSdk = 24          // Android 7.0+
    versionName = "1.2"
}

// CRÍTICO: no comprimir el modelo .tflite
androidResources {
    noCompress += "tflite"
}

dependencies {
    implementation(libs.androidx.compose.material3)   // UI
    implementation(libs.androidx.navigation.compose)      // NavGraph
    implementation(libs.tensorflow.lite)                // IA on-device
    implementation(libs.firebase.auth)                  // login
    implementation(libs.firebase.firestore)             // ScanRecord
    implementation(libs.firebase.storage)               // fotos
    implementation(libs.coil.compose)                   // imágenes
}
Qué decir en la exposición:
“Este archivo es la lista de ingredientes del proyecto. Sin estas dependencias no tendríamos interfaces Compose, ni Firebase para guardar usuarios y escaneos, ni TensorFlow Lite para la IA. La línea noCompress tflite es especialmente importante: si Android comprime el modelo, deja de funcionar en el celular.”
